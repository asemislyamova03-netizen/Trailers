## 1. Что уже есть в коде

| Место | Что хранит | Чего нет для себестоимости |
|---|---|---|
| `Item.unit`, `Item.base_price` | Учётная единица карточки и прайсовая цена продажи | Закупочной цены, валюты, НДС, слоя остатка |
| Матрицы `trailer_*_price_matrix.cost_price` | Ручная «себестоимость» опции каталога, валюта по умолчанию `KZT` | Связи с приходом, слоем, сменой, `ProducedUnit` |
| `InventoryReceiptPlanLine` | План: `quantity`, `unit` | Цены и документа |
| `InventoryOperation` тип `receipt` | Склад, зона, поставщик, план, автор | Отдельного номера первички: `document_ref` склеивается в `comment` |
| `InventoryOperationLine` | `quantity`, `unit`, `direction` | Суммы, цены, НДС, курса, исходной единицы |
| `InventoryBalance` | `quantity`, `reserved_quantity`, `unit` на склад+зону+номенклатуру | Денежного остатка и партии |
| `inventory_units.py` | Справочник единиц, алиасы, точность, запрет чужой единицы на приходе | Коэффициента кг↔т и спецификации тонна→шт/м/м² |
| `ItemBillOfMaterials` / line | Версия BOM, `quantity_per_unit`, `unit` компонента | Нормы отходов, выхода, цены |
| `apply_production_consumption` | Списание BOM × 1 шт на `ProducedUnit` при кнопке «+1» | Стоимости списания |
| `post_shift` | Факт `ProductionShiftMaterial` списывается до нуля; недостача без движения остатка; годный COMPONENT приходуется; прицеп создаёт `ProducedUnit` | BOM-калькуляции, стоимости брака, стоимости прицепа |
| `ProductionShiftOutput.defect_quantity` | Количество брака | Движения остатка и денег. Для COMPONENT в остаток идёт `quantity`, не `quantity − defect` |
| `ProducedUnit` | Заявка, смена, `unit_seq`, статус без VIN | Поля себестоимости |
| Уникальные индексы миграции `a7c8d9e0f1a2` | Один posted `production_issue` / `production_shortage` на строку материала смены и один `production_output_receipt` на строку выпуска | Идемпотентности денежной проводки |

Приход (`apply_inventory_receipt`) отклоняет строку, если единица строки не совпадает с `Item.unit`, и отклоняет приход в другую единицу при ненулевом остатке этой ячейки. При нулевом остатке единица строки баланса может быть перезаписана. Присваивание `item.unit = unit` ниже этой проверки сейчас недостижимо: до него единицы уже обязаны совпасть. Это ловушка, если проверку ослабят. Конверсия не должна менять `Item.unit`.

`_available_on_place` складывает количества одного `item_id` по нескольким зонам и не сравнивает `balance.unit`. Если в разных зонах у одной номенклатуры окажутся кг и шт, сумма будет бессмысленной. Себестоимость из такой суммы получать нельзя.

Два контура расхода уже разделены режимом зоны:

- `legacy_plus_one`: выпуск «+1» списывает BOM с общего остатка (`storage_area_id=None`, без зон направления). Смену провести нельзя: `require_direction_area` требует `shift_only`.
- `shift_only`: «+1» блокируется (`plus_one_blocked_reason`). Смена списывает факт материала с зоны направления, не формулу BOM.

Обратной блокировки нет. «+1», сделанный до открытия зоны, не запрещает позже провести смену по той же строке заявки и списать материал ещё раз. Для денег это запрещено отдельным правилом ниже, даже если количество когда-нибудь пропустят.

Отрицательный остаток смена не создаёт: `_allocate_issue_to_zero` списывает не больше наличия, хвост пишется как `production_shortage` без движения баланса. Недостача не получает себестоимость «из воздуха».

## 2. Цепочка стоимости

Себестоимость считается в деньгах и в учётной единице. Исходные количество, единица и цена документа не затираются.

```text
строка поступления
  цена и количество в исходной единице
  + подтверждённые доп. затраты в тенге
  − торговые скидки
  без потенциально возмещаемого НДС
        │
        ▼
подтверждённая конверсия → учётное количество и учётная единица
        │  общая сумма слоя не меняется
        ▼
слой остатка: учётный остаток + сумма слоя + стоимость единицы слоя
        │
        ▼
одно списание на смену / деталь / прицеп
        │
        ▼
стоимость годного выпуска и отдельно стоимость брака
```

Правила, которые не выбираются:

1. Кг и штуки не суммируются. Суммируются только деньги и только количества одной учётной единицы одного слоя или одного метода оценки.
2. Себестоимость единицы не равна «сумма документа / текущий `InventoryBalance.quantity`». Текущий остаток смешивает приходы, направления и уже списанное.
3. Конверсия количества не меняет общую стоимость слоя. Меняется только делитель (учётное количество).
4. Нет утверждённой спецификации — нет учётного количества, нет стоимости единицы, нет проводки остатка.
5. Слой не уходит ниже нуля.
6. Один физический расход имеет одну стоимостную проводку. «+1» и смена не списывают стоимость одного и того же выпуска дважды.
7. Факт складского прихода не создаёт право на зачёт НДС.

### 2.1. Строка поступления

Минимальный контракт строки (ещё не колонки базы):

| Группа | Поля |
|---|---|
| Исходный документ | тип источника, номер, дата, поставщик, ссылка на файл/внешний id |
| Исходное количество | `source_qty`, `source_unit`, `source_unit_price`, `source_line_amount` |
| Налог, отдельно от количества | сумма без НДС, код вида налогообложения, ставка на дату документа, сумма НДС, сумма с НДС |
| Валюта | код валюты, курс, дата курса, источник курса, сумма в тенге |
| Доп. затраты строки | доставка, пошлина, прочие, каждая со своим документом и признаком «в стоимость / потенциально к зачёту» |
| Конверсия | id и версия спецификации, коэффициент, точность, `accounting_qty`, `accounting_unit` |
| Слой | `layer_id`, сумма слоя в тенге, остаток количества слоя, остаток суммы слоя |

`Item.unit` остаётся учётной единицей номенклатуры. Исходная единица живёт только на строке документа.

### 2.2. Конверсия

| Переход | Условие | Отказ |
|---|---|---|
| кг ↔ т | Фиксированный размерный коэффициент 1 т = 1000 кг, версия спецификации, точность учёта кг/т = 3 знака | Нельзя подставить «примерно» |
| т → шт, м, м² | Только утверждённая спецификация конкретного `Item` или партии: масса штуки, профиль, длина, толщина, выход, отходы, версия, точность | Нет спецификации — проводка запрещена |
| та же единица | Коэффициент 1, версия всё равно фиксируется | — |

Спецификация версионируется. Проведённая строка хранит версию, которой пользовались. Смена нормы в карточке не переписывает старый слой.

Округление количества — по точности учётной единицы. Округление денег — до тиына (0,01 KZT). Общая сумма слоя хранится явно. Если сумму делят на штуки, остаток тиына сидит на последней единице, чтобы сумма единиц совпала с суммой слоя.

### 2.3. Слой и метод оценки

Слой принадлежит номенклатуре, складу, зоне (в том числе направлению) и учётной единице.

Открытый выбор HQ, в код не зашивать, пока нет решения:

| Метод | Смысл | Когда уместен |
|---|---|---|
| FIFO | Расход забирает самые ранние слои | Партии металла и покупных деталей |
| Средневзвешенная | Новая цена пересчитывается внутри одного ключа: номенклатура + склад + зона + учётная единица | Однородный материал без партий |
| Адресная идентификация | Стоимость сидит на конкретном `ProducedUnit` / будущем VIN | Готовый прицеп, не взаимозаменяемый с другим |

МСФО (IAS) 2 допускает FIFO и средневзвешенную; для невзаимозаменяемых единиц — адресную идентификацию. LIFO не предлагается. Какой стандарт реально обязателен заводу (полный МСФО, МСФО для МСБ или НСФО), по коду не видно. Это BLOCKED до учётной политики.

Средневзвешенная не пересекает зоны: легковой остаток и грузовой остаток не усредняются. И не пересекает единицы.

### 2.4. Списание на смену, деталь, прицеп

Списание ссылается на конкретный объект, а не на «склад вообще»:

| Контур | На что садится стоимость | Откуда количество |
|---|---|---|
| Смена, материал | `production_shift_material` и `InventoryOperation` типа `production_issue` | Факт смены, не формула BOM. Так уже делает `post_shift` |
| Смена, деталь COMPONENT | Годный приход `production_output_receipt` | `ProductionShiftOutput.quantity` |
| Смена, брак | Отдельная стоимостная строка без прихода в остаток, пока HQ не решит иначе | `defect_quantity`. Сейчас это только число |
| «+1» | `ProducedUnit`, операция `production_issue` | BOM × 1. Так делает `production_line_produce_one` |
| Прицеп | Конкретный `ProducedUnit` и будущий `trailer_id` | Адресная идентификация: сумма списанных слоев этой единицы |

BOM остаётся нормативной раскладкой. Факт смены может с ним не совпасть. Калькуляция прицепа по смене берёт фактическое списание, а не прайс `cost_price` и не `Item.base_price`. Сравнение факта с BOM — отдельный отчёт отклонений, не вторая проводка.

Запрет двойного списания: у `ProducedUnit` не больше одного набора материальных проводок. Если выпуск создан «+1», смена не создаёт второй набор на ту же единицу. Если выпуск создан сменой, «+1» не создаёт второй. Текущий код закрывает только вторую сторону и только пока зона в `shift_only`. До открытия учёта направления стоимостные проводки не включаются: остатки ещё не введены, отрицательный слой и «стоимость из пустого склада» запрещены.

Недостача (`production_shortage`) количество в балансе не двигает и слой не расходует. Себестоимость недостачи появляется только если позже найдут документ, который объясняет потерю уже оприходованного слоя. Подтверждение старшего такой документ не заменяет.

### 2.5. Годный выпуск и брак

Пул стоимости — это сумма списанных слоёв на смену или на единицу выпуска. Дальше пул делится между годным и браком. Количество годных в штуках и количество металла в кг остаются в своих единицах; между ними переносится только деньги.

Открытый выбор HQ (показывать оба, не выбирать молча):

1. Нормальные отходы, заложенные в утверждённой спецификации, входят в стоимость годных. Сверхнормативный брак списывается на расход периода и в остаток годных не кладётся. Это соответствует идее IAS 2: в запас не входят сверхнормативные потери.
2. Весь фактический брак несёт свою долю материальной стоимости (вплоть до чистой цены продажи, если брак можно продать). Годные получают остаток пула.

Текущий код не делает ни того, ни того: `defect_quantity` никуда не оценивается, а годный COMPONENT приходуется без денег.

Общие затраты (доставка на несколько строк, пошлина на декларацию, энергия смены) тоже открытый выбор базы распределения: по сумме без НДС, по массе, по объёму или явным процентом на строке. База обязана быть одной единицей измерения. Кг и штуки базой распределения быть не могут.

## 3. Доставка, пошлины, прочие, возвраты, валюта, НДС

Проверено 2026-09-28 по источникам из раздела 7. Ставка в код и в количество не зашивается. Право зачёта не выводится из факта прихода.

### 3.1. Что входит в стоимость запаса

По IAS 2 (п. 10–11, 16) в стоимость приобретения входят цена покупки, импортные пошлины и прочие налоги, кроме тех, которые потом возмещаются, плюс доставка, погрузка и иные прямые затраты до текущего места и состояния. Скидки вычитаются. Не входят сверхнормативные потери, общие административные расходы и расходы на продажу.

Отсюда для завода:

| Затрата | В стоимость слоя | Не в стоимость слоя |
|---|---|---|
| Цена поставщика без НДС | Да | — |
| Доставка и прочие прямые расходы без возмещаемого налога | Да, после явного распределения | — |
| Таможенная пошлина, таможенный сбор, если они не возмещаются | Да | — |
| НДС, который можно отнести в зачёт | Нет. Хранится отдельной суммой «потенциально к зачёту» | Пока нет отметки/подтверждения, это ещё не признанный зачёт и не расход |
| НДС, который нельзя зачесть | Да, отдельной строкой «налог в стоимости», с причиной | — |
| Скидка, возврат части цены | Уменьшает стоимость | — |

Пока не известно, состоит ли завод на учёте по НДС и есть ли облагаемый оборот, нельзя заранее сказать, что «НДС всегда мимо себестоимости» или «НДС всегда внутри». Оба атрибута обязательны. Решение по строке явное.

Отдельный путь, не равный обычному зачёту и не равный включению в себестоимость: по перечню Правительства часть импорта уплачивает НДС методом зачёта (постановление Правительства РК от 31.12.2025 № 1199, ссылка на ст. 508 и 509 НК № 214-VIII, ввод с 2026-01-01). Попадает ли конкретный код ТН ВЭД металла или комплектующих в перечень — не проверялось по номенклатуре завода. BLOCKED.

### 3.2. Три источника прихода — не один документ

| Источник | Документ права на зачёт, если зачёт вообще возможен | Дата, которая важна для зачёта | Складской остаток |
|---|---|---|---|
| Местный поставщик | ЭСФ с выделенным НДС и ИИН/БИН поставщика. Плательщик НДС должен поставить в ИС ЭСФ отметку о зачёте до декларации | Дата получения товара. Дополнительный ЭСФ — по дате его выписки. Исправленный — по периоду аннулированного, кроме случая разных налоговых периодов оборота | Приход только проведённым складским документом |
| Третья страна | Декларация на товары. Зачёт не больше НДС, уплаченного в бюджет РК и не подлежащего возврату | Дата выпуска товара по таможенному законодательству | ДТ не двигает остаток сама |
| ЕАЭС | Заявление о ввозе товаров и уплате косвенных налогов (в налоговой отчётности — форма 328.00). Это не ДТ | Дата платежа в бюджет, но не ранее 20-го числа месяца, следующего за налоговым периодом | Заявление не двигает остаток само |

Несколько документов могут висеть на одном складском поступлении: накладная, ЭСФ, ДТ или заявление, счёт на доставку. Поздняя сверка допустима: слой можно провести по количеству только после подтверждённой конверсии, а налоговый статус НДС может ещё быть «не подтверждён». Неподтверждённый НДС не молча попадает в стоимость и не молча считается зачтённым.

Условия зачёта по ст. 480 НК № 214-VIII, которые нельзя пропустить: получатель — плательщик НДС, стоящий в базе налогоплательщиков; товар будет использован в облагаемом обороте; есть надлежащий документ; по электронному счёту-фактуре сумма отражена в ИС ЭСФ, и до декларации стоит отметка о признании зачёта. Несколько оснований — зачёт один раз, по самому раннему.

Корректировка и возврат — новый документ, не правка проведённой строки:

- возврат товара поставщику уменьшает слой, если количество ещё лежит; если слой уже съеден, остаток слоя уменьшается до нуля, а хвост суммы — открытый выбор: ретроспектива на уже списанные выпуск/прицеп или отклонение текущего периода;
- изменение цены без возврата количества — денежная корректировка слоя и, при выборе ретроспективы, уже списанной стоимости;
- дополнительный ЭСФ двигает налоговый период зачёта по своей дате выписки, а не «задним числом в остаток».

Валюта: сумма документа хранится в валюте контракта и отдельно в тенге. Курс, дата и источник (официальный курс Национального Банка) обязательны. Какую дату считать датой операции (дата ЭСФ, дата выпуска ДТ, дата оприходования, дата оплаты) — открытый выбор учётной политики. IAS 21 требует курс на дату операции; политика должна назвать эту дату. Курс не выдумывается и в этом документе не фиксируется числом.

## 4. Синтетический пример

Дата документа в примере: 2026-09-15. Поставщик местный. Номенклатура `STEEL-SHEET`, учётная единица кг. Валюта KZT. Метод в примере для расхода — отдельный слой (как FIFO), чтобы было видно равенство. Средневзвешенная показана рядом как другой открытый вариант, в итог равенства она не подмешана.

Допущение, явно помеченное: покупатель — плательщик НДС и собирается использовать металл в облагаемых продажах прицепов. Поэтому НДС в стоимость не входит. Это не доказанный статус завода.

### 4.1. Равенство до и после конверсии

| Шаг | Количество | Деньги, KZT |
|---|---|---|
| Строка: 1,000 т × 500 000,00 за тонну, без НДС | 1,000 т | 500 000,00 |
| НДС 16% на эту дату, если действует базовая ставка ст. 503.1 | — | 80 000,00 потенциально к зачёту, в слой не входит |
| Доставка без НДС, один документ, 100% на эту строку | — | 20 000,00 в слой |
| НДС доставки 16% | — | 3 200,00 потенциально к зачёту, в слой не входит |
| Пошлина | — | 0,00 |
| Стоимость до конверсии | ещё тонна | 520 000,00 |
| Спецификация `DIM-MASS-v1`: 1 т = 1000 кг | 1 000,000 кг | 520 000,00 |
| Стоимость 1 кг | — | 520,00 |
| Проверка | 1 000,000 × 520,00 | 520 000,00 |

Сумма до конверсии равна сумме после. НДС 80 000,00 + 3 200,00 в равенство запаса не входит.

Если бы этот НДС был невозмещаемым, в слой добавились бы 80 000,00, стоимость стала бы 600 000,00, кг стоил бы 600,00. Это другой, явный сценарий. В основной итог он не смешан.

Отказ: та же тонна профиля «перевести в штуки» без спецификации массы штуки, профиля, длины, толщины, выхода и отходов. Учётного количества нет, стоимости единицы нет, остаток не двигается.

Тиын: сумма слоя 100 000,00 при 3 шт учётных. В слое хранится 100 000,00. Раскладка по штукам 33 333,33 + 33 333,33 + 33 333,34. Последняя штука держит остаток тиына.

### 4.2. Два направления, годное и брак

Подписанный перенос, не авторазбиение:

| Зона | Количество | Стоимость |
|---|---|---|
| `DIR_LIGHT` | 600,000 кг | 312 000,00 |
| `DIR_CARGO` | 400,000 кг | 208 000,00 |
| Итого | 1 000,000 кг | 520 000,00 |

Легковая смена списывает 100,000 кг. Стоимость списания 52 000,00. Грузовая смена списывает 50,000 кг. Стоимость 26 000,00. Это разные слои разных зон. Их кг можно сложить только как 150 кг одного материала; к штукам панелей они не прибавляются.

Легковой выпуск: 8 годных панелей (шт) и 2 брака (шт). Иллюстрация распределения «доля штук», не решение HQ: годные 8/10 × 52 000,00 = 41 600,00 (5 200,00 за панель), брак 10 400,00 на расход периода, в остаток не приходуется. Проверка: 41 600,00 + 10 400,00 = 52 000,00.

Дальше один прицеп забирает 8 панелей адресной идентификацией: 41 600,00 материала `STEEL-SHEET` через панели. Прочие строки BOM в пример не входят. `base_price` и `cost_price` каталога здесь не используются.

Остаток после двух списаний:

| Зона | Остаток кг | Остаток денег |
|---|---|---|
| Легковые | 500,000 | 260 000,00 |
| Грузовые | 350,000 | 182 000,00 |
| Уже списано на смены | 150,000 | 78 000,00 |
| Сумма | 1 000,000 | 520 000,00 |

Рядом, не в этот итог: если бы на легковых уже лежало 200 кг по 400,00 (80 000,00), FIFO списал бы 100 кг по 400,00 = 40 000,00 из старого слоя. Средневзвешенная на ключе «лист + завод + легковые + кг» дала бы (80 000 + 312 000) / 800 кг = 490,00 и списание 49 000,00. Цифры разные. Метод не выбран.

### 4.3. Поздняя корректировка первички

Кредит-нота уменьшает цену металла на 10 000,00 без НДС (10,00 на каждый исходный кг). НДС к зачёту уменьшается отдельным дополнительным ЭСФ, период зачёта — по дате выписки дополнительного счёта.

На момент корректировки уже списано 150 кг, лежит 850 кг.

| Открытый вариант | На остаток 850 кг | На уже списанные 150 кг |
|---|---|---|
| Ретроспектива | −8 500,00 | −1 500,00 на смены/прицеп |
| Только остаток, разница периодом | −8 500,00 | 1 500,00 отклонение периода, выпуск не переписывается |

Оба варианта сохраняют 10 000,00. Какой обязан заводу — не выводить из Flask.

## 5. Контракт Flask и Flexity

Полный бухучёт в legacy не строится. Рабочие остатки этим документом не открываются.

Flask hotfix, когда будет отдельное разрешение на код, хранит только операционный контракт:

- исходные количество, единица, цена и суммы строки;
- налоговые атрибуты и курс отдельно от `quantity`;
- версию конверсии и учётное количество;
- слой с суммой и запретом минуса;
- ссылку списания на смену, `ProducedUnit` или прицеп;
- идемпотентность и обратную проводку документом, а не правкой истории.

План счетов, декларация НДС, проводки Дт/Кт и закрытие месяца остаются вне Trailers.

Flexity, позже:

| Вопрос | Куда |
|---|---|
| Слои, конверсия, среднее/FIFO, запрет минуса | универсальный `inventory` |
| Первичка, НДС, курс, зачёт, пошлины | универсальный `accounting` / документы |
| BOM прицепа, VIN, легковые/грузовые, смена | `industry_trailers` |
| Себестоимость прицепа | стык: inventory отдаёт стоимость списанных слоёв, industry_trailers собирает единицу VIN |

`cost_price` в матрице опций остаётся коммерческой оценкой каталога, пока её явно не свяжут со слоем. Сама по себе она не себестоимость выпуска.

## 6. Обмен 1С и ИС ЭСФ

Этот раздел — тот же результат задачи №2. Живой обмен и учётные данные не использовались. Прямой API не обещается, пока нет подтверждения прав конкретной базы.

### 6.1. Что удалось установить без входа в чужие системы

| Канал | Что публично есть | Чего нет для завода |
|---|---|---|
| 1С, файл EnterpriseData | Обмен XML-файлом: сообщение и квитанция с номером принятого сообщения. Сертификация ИС ЭСФ для самого файла не требуется | Неизвестна конфигурация 1С завода, есть ли в ней план обмена и какие объекты он отдаёт. BLOCKED |
| 1С, другой файл (CommerceML, выгрузка таблиц, отчёт в Excel) | Зависит от конфигурации. Как возможность «файл», не как обещание API | Тот же BLOCKED |
| ИС ЭСФ | У КГД опубликован API: SOAP, XML-шаблоны, SDK, подпись сертификатом НУЦ, идентификатор учётной системы. Есть отдельные сервисы счетов-фактур и модуль виртуального склада | Нет подтверждения, что этой организации выдан доступ, сертификат и роль. Вызов API отсюда не делался |
| Виртуальный склад ИС ЭСФ | Государственный контур СНТ/склада налогоплательщика | Это не остаток цеха Кокшетау. Путать нельзя |

Пока BLOCKED не снят, рабочий путь проектирования — файл/XML после сверки человеком. Отправка в ИС ЭСФ и запись в 1С включаются отдельным решением, когда будут роль, сертификат и название конфигурации.

### 6.2. Источник истины

| Объект | Источник истины | Что не имеет права писать остаток само |
|---|---|---|
| Номенклатура завода | Карточка `Item` во Flexity/Trailers после сопоставления | Импорт 1С создаёт черновик сопоставления, не подменяет `Item.unit` |
| Код номенклатуры 1С и код ЭСФ | Внешняя система, в карте идентификаторов | Flask не назначает «официальный» код молча |
| Складской приход | Один проведённый документ завода | Ни документ 1С, ни ЭСФ |
| Себестоимость для управленческого цеха | Слой из раздела 2 | Прайс `cost_price` и цена продажи |
| Себестоимость для сдачи отчётности | Учётная политика и бухгалтерская база. Пока это не Flexity accounting, не считать Flask главной книгой | Слой Flask не проводит декларацию |
| Реализация | Документ продажи завода | Не создаёт юридическую ЭСФ |
| ЭСФ | ИС ЭСФ после явной отправки | Проведение реализации |
| Остаток цеха | `InventoryBalance` / слой после открытия учёта | Виртуальный склад и регистр 1С |

Карта идентификаторов хранит пару внешних id, версию сообщения и наш id. Повтор той же версии не создаёт второй приход. Новая версия — черновик расхождений, не новая партия.

Цепочка: черновик → сверка → утверждение → проводка склада или отправка ЭСФ. Ошибка пишется в журнал и не откатывается молча. Исправление и отзыв — новый документ со ссылкой на исходный.

Синтетический случай: 1С и ЭСФ содержат один и тот же приход металла 1 т. Это один складской документ со двумя связанными основаниями. Остаток 1 000 кг один раз, не два.

## 8. Порядок и решения HQ

Код не начинать, пока нет явных ответов:

1. Метод оценки покупного ТМЦ: FIFO или средневзвешенная внутри ключа «номенклатура + склад + зона + единица». Для VIN — адресная идентификация.
2. База распределения доставки, пошлины и прочих общих сумм.
3. Брак: сверхнормативный на период или доля стоимости на брак.
4. Корректировка после списания: ретроспектива или отклонение периода.
5. Дата курса.
6. Статус плательщика НДС и облагаемость продаж прицепов. Без этого нельзя проставить признак «в стоимость / к зачёту» боевым данным.
7. Конфигурация 1С и наличие права на ИС ЭСФ.

Порядок после этих ответов, каждый шаг отдельным разрешением:

1. Контракт полей и отказов конверсии, без остатков.
2. Черновик поступления с несколькими основаниями и налоговыми атрибутами. Проведение слоя выключено, пока зона не открыта инвентаризацией.
3. Стоимость списания на смену и `ProducedUnit`, с запретом второго контура.
4. Только потом файл сверки с 1С и ЭСФ. Отправка наружу — отдельное решение.

Не делать в legacy: план счетов, автоматический зачёт, автоматическую ЭСФ, угадывание тонна→штуки, смешение зон, включение `shift_only`, миграцию на живой базе.

## 9. Доказано и BLOCKED

Доказано чтением базы `1e0f484`:

- цены продажи и ручной `cost_price` каталога не связаны с `InventoryOperation`, BOM и `ProducedUnit`;
- строка складского движения хранит только количество и единицу;
- кг↔т в коде нет; чужая единица на ненулевом остатке отвергается; суммы кг и шт по разным зонам код остатка не запрещает;
- «+1» и смена списывают разное количество (BOM против факта) и в текущем режиме зоны одновременно не проводятся, но смена после уже сделанного «+1» не заблокирована;
- смена не уходит в минус; недостача остаток не двигает; брак не оценивается;
- документ прихода не структурирован и не отличим как ЭСФ, ДТ или заявление ЕАЭС;
- `docs/ai/MIGRATION_TO_FLEXITY.md` отсутствует.

BLOCKED:

- живые остатки, инвентаризация, открытие зон, любая запись в рабочую БД;
- статус НДС завода, ТН ВЭД и попадание в перечень метода зачёта;
- учётная политика: стандарт запасов, метод оценки, дата курса, распределение, брак, ретроспектива;
- актуальная после 01.01.2026 редакция порядка отметки на заявлении ЕАЭС;
- полный HTML статей на Әділет в этой сессии не прочитан, опора на сноску Әділет и датированную republication;
- имя конфигурации 1С, права и сертификат ИС ЭСФ;
- курс валюты числом и любая ставка «навсегда».
