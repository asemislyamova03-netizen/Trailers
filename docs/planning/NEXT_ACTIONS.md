## Следующие действия

1. Проверить локально изменённый контур ролей: менеджер отдаёт потребности в производство, логист видит только VIN-реестр, производственные кнопки для менеджера неактивны.
2. Подтянуть последние изменения на сервер и перезапустить приложение после отдельного подтверждения.
3. На сервере запустить проверку синтаксиса через рабочий venv: `venv/bin/python -m py_compile views.py`.
4. Проверить меню логиста: вход должен вести в `Реестр VIN`, без блока потребностей/производства.
5. Проверить меню менеджера: в производственном блоке должны быть новые потребности и кнопка `Отдать в производство`.
6. Проверить, что менеджер может привязать VIN к выпущенной единице без VIN, а производственник по-прежнему выпускает изделие кнопкой `Выпущено 1 шт.`.
7. Проверить, что менеджер может отправить готовый прицеп со склада выпуска на свой склад кнопкой `Переместить на мой склад`, а логист не выполняет это действие.
8. Проверить сортировку реестра VIN у логиста: сверху должен быть самый большой порядковый номер `serial7`.
9. Проверить в заказе `ORD-000043`: добавление второй другой конфигурации в производство создаёт отдельную строку заказа и `SupplyNeed` с `order_line_id`.
10. Проверить создание договора по заказу с разными строками: в `sales_contract_line` должны появиться строки, печатная спецификация должна вывести несколько позиций.
11. Подготовить безопасную интеграцию Kaspi: определить API заказов/платежей, место хранения токена в env/настройках и модель сопоставления Kaspi-заказа с `CustomerOrder`.
12. Добавить редактирование/удаление строк заказа до выдачи документов.
13. Добавить построчную отгрузку/закрытие заказа по нескольким прицепам.
14. Спроектировать выбор шаблонов договоров по группе/ОТТС/модификации.
15. Спроектировать списание комплектующих и полуфабрикатов по спецификации при выпуске единицы прицепа.
16. Добавить мобильный интерфейс смен сотрудников: открыть смену, выбрать участок, закрыть смену с результатом или без результата.

## Ближайшая техническая задача

- Проверить полный менеджерский цикл: отдать потребность в производство, привязать VIN, переместить готовый прицеп на свой склад, принять входящее перемещение.

## Ближайшая бизнес-задача

- Подтвердить новую модель производства: участки, склады комплектующих/полуфабрикатов, сотрудники, смены и результаты месяца для директора.
- Уточнить правила для разных шаблонов договоров по группам/ОТТС/модификациям и будущие этапы оплат.
- Уточнить сценарий Kaspi: это импорт заказов магазина, платежные ссылки/QR, статусы оплат или всё вместе.

## Что нельзя забыть

- Не смешивать trailers с clinic app и flexity admin.
- Цены по конфигурации могут быть не заполнены и не должны блокировать заказ.
- Источник выбора параметров конфигуратора - матрица допустимости, а не справочник номенклатуры и не ценовые матрицы.
- Разные прицепы в одном заказе должны жить как разные строки заказа, а не как количество одной строки.
- Удаление заказа должно оставаться безопасным: нельзя удалять заказ, если уже есть резервы, VIN, договор, оплаты, производство, перемещения, документы или отгрузка.
- Токен Kaspi нельзя коммитить в репозиторий; хранить только в переменных окружения или закрытых настройках сервера.
