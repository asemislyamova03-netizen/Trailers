3. На сервере запустить проверку синтаксиса через рабочий venv: `venv/bin/python -m py_compile views.py`.
4. Проверить меню логиста: вход должен вести в `Реестр VIN`, без блока потребностей/производства.
5. Проверить меню менеджера: в производственном блоке должны быть новые потребности и кнопка `Отдать в производство`.

9. Подготовить безопасную интеграцию Kaspi: определить API заказов/платежей, место хранения токена в env/настройках и модель сопоставления Kaspi-заказа с `CustomerOrder`.
10. Добавить редактирование/удаление строк заказа до выдачи документов.
11. Добавить построчную отгрузку/закрытие заказа по нескольким прицепам.
12. Спроектировать выбор шаблонов договоров по группе/ОТТС/модификации.
13. Спроектировать списание комплектующих и полуфабрикатов по спецификации при выпуске единицы прицепа.
14. Добавить мобильный интерфейс смен сотрудников: открыть смену, выбрать участок, закрыть смену с результатом или без результата.

## Ближайшая бизнес-задача

- Подтвердить новую модель производства: участки, склады комплектующих/полуфабрикатов, сотрудники, смены и результаты месяца для директора.
- Уточнить правила для разных шаблонов договоров по группам/ОТТС/модификациям и будущие этапы оплат.
- Уточнить сценарий Kaspi: это импорт заказов магазина, платежные ссылки/QR, статусы оплат или всё вместе.

## Что нельзя забыть

- Не смешивать trailers с clinic app и flexity admin.
- Цены по конфигурации могут быть не заполнены и не должны блокировать заказ.
- Источник выбора параметров конфигуратора - матрица допустимости, а не справочник номенклатуры и не ценовые матрицы.
- Разные прицепы в одном заказе должны жить как разные строки заказа, а не как количество одной строки.
- Удаление заказа должно оставаться безопасным: нельзя удалять заказ, если уже есть резервы, VIN, договор, оплаты, производство, перемещения, документы или отгрузка.
- Токен Kaspi нельзя коммитить в репозиторий; хранить только в переменных окружения или закрытых настройках сервера.
