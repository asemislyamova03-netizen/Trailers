## Что уже реализовано

- Базовая структура проектного контекста и planning-документов.
- Исправлена обработка конфигуратора при переводе/сохранении заказа в производство через форму редактирования.
- Форма заказа в производство переведена на общую логику конфигуратора: доступные параметры фильтруются по матрице допустимости, ОТТС/VIN показывают ошибки конфигурации явно.
- В справочнике ОТТС/VIN-модификаций номер и модификация ОТТС выбираются из активного справочника ОТТС, а не вводятся свободным текстом.
- В справочнике групп номер ОТТС выбирается из активного справочника ОТТС.
- В подборе прицепа спецпараметры выводятся из матрицы допустимости; ценовые матрицы не скрывают допустимые параметры.
- В подборе прицепа списки параметров динамически обновляются после выбора группы/параметров и синхронизируют hidden-поля действий.
- Конфигуратор больше не подставляет `NOOK` и `NONE` автоматически, если опорное колесо или тент не выбраны.
- Поиск ОТТС/VIN-модификации учитывает выбранную высоту борта для любых типов кузова, включая `GRAINTRAILER`.
- Заказ в производство поддерживает количество больше 1 для одной конфигурации: сумма от конфигуратора умножается на количество, производственная потребность синхронизируется по количеству.
- Добавлена основа для многострочных заказов и договоров: `CustomerOrderLine`, `SalesContractLine`, привязка VIN/резервов/производства к строке заказа.
- Добавлена основа производственного модуля: участки/цеха, сотрудники производства, смены, результаты смен, спецификации номенклатуры, склады комплектующих и полуфабрикатов.
- Менеджерам открыт раздел производства и перемещения; у логиста в навигации оставлен простой логистический контур и реестр VIN.
- Запуск потребностей в производство перенесён к менеджеру: менеджер видит новые потребности своего склада и отдаёт их в производство.
- Логистический контур для роли логиста сужен до реестра VIN; рабочий стол логиста перенаправляет логиста в VIN-реестр, чтобы он не запускал производство, не резервировал/привязывал VIN и не выполнял менеджерские операции.
- Менеджер может привязать VIN к выпущенной единице из своего производственного блока; фактический выпуск изделия остаётся доступен только производственникам.
- Менеджер может отправить готовый прицеп со склада выпуска на свой склад из вкладки готовых к отправке прицепов; действие доступно только если склад назначения совпадает со складом менеджера.
- Реестр VIN для логиста сортируется по порядковому номеру VIN: сверху отображается самый большой `serial7`, а не последняя внесённая запись.
- Менеджеру открыто изменение комплектации прицепа и выпущенной единицы без VIN; пустые опциональные параметры не должны автоматически превращаться в тент/каркас 90 или опорное колесо.
- Проверка изменения комплектации больше не считает смену высоты борта сменой размера рамы/кузова: база сравнивается по группе, коду размера кузова и количеству осей.
- Реестр VIN адаптирован для работы логиста с телефона: кнопка `Открыть` находится рядом с VIN, второстепенные колонки скрываются на малых экранах.
- Администратору добавлена корректировка и удаление ошибочно созданных VIN на начальном этапе.
- В карточке заказа добавлен блок позиций: можно добавить отдельную позицию из наличия с резервом VIN или позицию в производство с созданием потребности; сумма заказа пересчитывается по строкам.
- В карточке заказа добавлено безопасное управление позициями до выдачи документов: редактирование количества/цены/комментария и удаление строки без резервов, VIN, производства, перемещений, договора и других связанных операций.
- Подбор прицепа можно открыть из существующего заказа и добавить другую конфигурацию отдельной строкой: из наличия резервируется выбранный VIN, для производства создаётся новая позиция и `SupplyNeed` по выбранной конфигурации.
- Администратору добавлено безопасное удаление заказа: удаление блокируется, если есть договор, оплаты, резервы, VIN, производство, перемещения, выпуск, документы или отгрузка.

## Риски

- Не смешать бизнес-логику trailers с другими проектами.
- При неверной обработке конфигуратора заказ может сохраниться без ОТТС/VIN-модификации, что ломает дальнейшую VIN-логику.
- Незаведённые цены допустимы, поэтому отсутствие цены должно оставаться предупреждением, а не блокировкой.
- Полный пользовательский сценарий двух разных прицепов в одном заказе реализован частично: добавление, безопасное редактирование/удаление строк и построчная отгрузка есть, но ещё нужно проверить привязку VIN к производственной строке на серверных данных.
- Автоматическое списание комплектующих/полуфабрикатов по спецификации ещё не включено в бизнес-операции выпуска.
- Текущий сервер/IP не подходит для проверки Kaspi API: `google.com` отвечает, а `kaspi.kz` уходит в timeout. Нужна проверка на хостинге организации или другом IP.
- Запчасти и комплекты без VIN пока не имеют отдельного жизненного цикла; ручные правки таких заказов через прицепную складскую логику могут исказить учет.
- Миграция добавляет много новых таблиц и полей; перед серверным обновлением нужен backup базы.
- После включения блокировки отгрузки без реализации пользователям нужно сначала создавать и проводить реализацию по сделке.
